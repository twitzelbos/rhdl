# `rhdl-alto`

The **Xerox Alto** (1973) microengine in RHDL — Tier C flagship core
#2 per [`tier-c-flagship-cores.md`](../../tier-c-flagship-cores.md) §5.

The Alto runs CPU instructions, display refresh, disk I/O, Ethernet
packets, and mouse input **all from one shared microengine** —
sixteen priority-ordered hardware tasks taking turns on a single
horizontal-microcode pipeline.  Implementing the Alto in RHDL
demonstrates that the language can express the most aggressively
heterogeneous digital design ever shipped, the abstraction that
descended into x86 microcode and modern microsequencers.

This crate is built **per the published phased roadmap** — Phase 1
(microengine skeleton) is what currently ships; Phases 2-8 land in
later PRs.

---

## Status — Phases 1 + 2 + 3 (foundation through disk subsystem)

Phase 1 (universal microengine) and Phase 2 (16-task arbiter as
an [`rhdl-rule`] kernel) shipped earlier.  This PR adds **Phase 3
foundations**: the simulated Diablo 31 disk drive widget, the
disk-controller register file, a 256-word memory subsystem stub,
and the **first per-task body specialization** — Disk Sector and
Disk Word task bodies diverge from the generic shape to bump
dedicated counters.

### What's in Phase 1

- [`isa`](src/isa.rs) — 32-bit microinstruction format, all four
  per-field enums (`AluFunction`, `BusSource`, `F1Function`,
  `F2Function`), packed/unpacked round-trip helpers.
- [`alu`](src/alu.rs) — pure-combinational kernel implementing the
  16 Alto ALU functions (BUS, T, BUS±T, BUS&T, BUS|T, BUS^T, ±1,
  BUS+SKIP, BUS&¬T, etc.).  Carry-out exposed for
  `F2 = AluCarryToNext` branching.
- [`regfile`](src/regfile.rs) — R-register file (32 entries × 16
  bits).  Single read port + single write port; `R0` is a normal
  R/W register (unlike RV32I's hardwired-zero `x0`).
- [`microcycle`](src/microcycle.rs) — shared per-cycle execution
  kernel (`compute_cycle`).  Pure-combinational; takes the
  current state + microinstruction, returns the candidate next
  state.  Used by both the single-task microengine and the
  16-task system.
- [`microengine`](src/microengine.rs) — 2-stage MIF/MIE pipeline
  for the single-task case.  10-bit MPC, T register, L register,
  R-register file.  Universal F1 codes (shifts on L) and universal
  F2 codes (BusEqZero, ShiftLessThanZero, ShiftEqZero, BusToNext,
  AluCarryToNext) for conditional branching.

### What's in Phase 2 — **16-task arbiter as `rhdl-rule` kernel**

[`task_system`](src/task_system.rs) — the Alto's defining
microarchitectural feature, expressed in the most BSV-natural way
possible.  16 hardware tasks, 16 `#[rule]` methods on one impl
block, priority arbitration generated by the [`rhdl-rule`]
scheduler from `#[rule(priority = N)]` annotations.

```rust
#[rule_kernel_attr]
impl AltoTaskSystem {
    #[rule(priority = 0)]   // highest — fires first when guarded
    fn task_15(ctx: &mut RuleCtx<Self>, i: AltoIn) {
        guard!((i.wakeups & bits::<16>(0x8000)) != bits::<16>(0));
        // ... per-task MPC update + last_task tag ...
    }

    #[rule(priority = 1)]
    fn task_14(ctx: &mut RuleCtx<Self>, i: AltoIn) { /* ... */ }

    // ... 16 rules total, descending priority ...

    #[rule(priority = 15)]   // lowest — Emulator task default
    fn task_0_emulator(ctx: &mut RuleCtx<Self>, i: AltoIn) { /* ... */ }
}
```

The 16 tasks naturally compete via mutual exclusion: they all
write to the same shared state (`task_mpc`, `last_task`,
`any_running`), so the scheduler fires at most one per cycle —
the highest-priority one whose `wakeup` bit is set.  This is the
**direct, idiomatic encoding of how the Alto's actual hardware
arbiter works**, in 16 lines of Rust per task.

[`rhdl-rule`]: ../rhdl-rule/

### What's in Phase 3 — disk subsystem foundation + first body divergence

- [`diablo_disk`](src/diablo_disk.rs) — simulated Diablo 31 fixed
  disk: 2 heads × 203 cylinders × 12 sectors × 256 words/sector
  (~2.4 MB total).  Provides `sector_mark` (rotational tick once
  per sector) and `word_strobe` (DMA word ready) outputs that
  drive the disk-task wakeups; sector-buffer read/write port for
  per-word DMA.
- [`disk_controller`](src/disk_controller.rs) — KSTAT / KDATA /
  KCOM / KADR / KCWA / KCWD register file, with field-decoded
  KADR (cylinder / head / sector) routed to the disk drive.
- [`memory`](src/memory.rs) — 256-word main-memory stub
  (Phase-3.5 will parameterize and back with `SyncBRAM`).
- [`task_system`](src/task_system.rs) — Task 1 (Disk Sector) and
  Task 2 (Disk Word) bodies now diverge from the generic shape.
  Both bump dedicated `disk_sector_count` / `disk_word_count`
  registers in addition to the generic per-task work.  This is
  the first PR where rule bodies specialize per task.

### What's deferred to Phase 3.5 (per `tier-c-flagship-cores.md` §5.5)

The published Phase 3 plan calls for "boot the original Alto disk
image far enough to get to the operating system loader."  That
requires three additional pieces this PR does **not** include:

1. **Real Alto microcode** loaded into the microengine ROM
   (sourced from the PARC archive / Bitsavers).
2. **Original Alto disk image** loaded into `DiabloDisk`
   (sourced from CHM / Bitsavers).
3. **End-to-end DMA** between `Memory` and `DiabloDisk` driven by
   the Disk Sector / Disk Word task bodies via the controller.

The Phase-3 widgets here are the foundation for that work; Phase 3.5
will source the binary assets and wire the DMA path.

## Capabilities (Phase 1)

### Microinstruction format

A single 32-bit horizontal microinstruction encodes:

```text
 [31:27]  RSEL    — R-register select (5 bits → 32 registers)
 [26:23]  ALUF    — ALU function (4 bits → 16 ops)
 [22:20]  BS      — Bus source (3 bits → 8 sources)
 [19:16]  F1      — F1 auxiliary function (4 bits → 16 codes)
 [15:12]  F2      — F2 auxiliary function (4 bits → 16 codes)
 [11]     T_LOAD  — latch T from BUS this cycle
 [10]     L_LOAD  — latch L from ALU result this cycle
 [9:0]    NEXT    — next microinstruction address (10 bits → 1024-entry RAM)
```

The same `Microinstruction` struct is used in tests (assembled by
hand) and in the kernel (decoded by `unpack_kernel`); the round-trip
via `pack`/`unpack` is the bridge to microcode binaries.

### ALU (16 functions)

All 16 ALUF codes per the Alto Hardware Manual §2.5: BUS, T,
BUS|T, BUS&T, BUS^T, BUS+1, BUS-1, BUS+T, BUS-T, BUS-T-1,
BUS+T+1, BUS+SKIP (carry-skip), BUS·T (alternate AND), BUS&¬T
(bit-mask), plus undefined codes 14/15 (treated as BUS).

### Conditional branching via F2

- `F2 = BusEqZero` → set NEXT bit 0 if `bus == 0`
- `F2 = ShiftLessThanZero` → set NEXT bit 0 if shifted-L's MSB is 0
- `F2 = ShiftEqZero` → set NEXT bit 0 if shifted-L is 0
- `F2 = BusToNext` → OR low bits of bus into NEXT (computed go-to)
- `F2 = AluCarryToNext` → set NEXT bit 0 if ALU carry-out

### L-register shifts via F1

- `F1 = LeftShift1` → L ← L << 1
- `F1 = RightShift1` → L ← L >> 1
- `F1 = LeftCycle8` → L ← rotate-left-by-8

## Testing

**63 tests pass** across Phases 1, 2, and 3:

| File | Tests | Coverage |
|------|-------|----------|
| `tests/alu.rs` | 20 | every ALUF code + carry-out + reserved codes + iverilog round-trip |
| `tests/regfile.rs` | 4 | write-then-read, R0-is-writable, independent slots, iverilog round-trip |
| `tests/microengine.rs` | 6 | T-load, L-load, two-step program, F1 left-shift looping, F2 branch-on-zero, iverilog round-trip |
| `tests/task_system.rs` | 14 | per-task wakeup, priority arbitration, wakeup gating, per-task MPC isolation, **Phase-3: per-task body divergence — disk counters increment only on the matching task**, iverilog round-trip |
| `tests/diablo_disk.rs` | 8 | sector_mark cadence + word-buffer round-trip + transfer-active gating + reset semantics + iverilog round-trip |
| `tests/disk_controller.rs` | 4 | per-register write/read round-trip + KADR field decode + iverilog round-trip |
| `tests/memory.rs` | 4 | write/read round-trip + per-address independence + read-en gating + iverilog round-trip |
| `tests/disk_dma_integration.rs` | 3 | **DiabloDisk → AltoTaskSystem composition: 3 sector marks → 3 Disk-Sector firings; Disk Word starves Emulator under priority pressure** |
| **Total** | **63** | |

```sh
cargo test -p rhdl-alto
```

Each test runs in milliseconds.  The iverilog round-trip tests
verify the emitted Verilog (RTL + NTL) round-trips through
[Icarus Verilog](https://steveicarus.github.io/iverilog/) and
produces byte-identical waveforms — the same ground-truth check
the rest of the workspace uses.

### Validation roadmap (per `tier-c-flagship-cores.md` §5.6)

Future phases will add the four-layer validation surface:

- **L1 — Per-microinstruction kernel tests** (this PR's 30 tests
  are the start; ~100 expected by Phase 2).
- **L2 — Per-task tests** (Phase 2+: each of the 16 tasks).
- **L3 — Real microcode binaries** (Phase 3+: load original Alto
  microcode binary from PARC archives; lockstep with ContrAlto).
- **L4 — Cycle-equivalence with ContrAlto** (Phase 7: full disk
  boot lockstep against the LCM emulator).
- **L5 — Smalltalk-76 demo** (Phase 7 showcase).

ContrAlto is cycle-accurate to original Alto hardware, so L4 is an
unusually strong gold reference.

## Crate layout decision

`tier-c-flagship-cores.md` §5.7 specifies the deliverables go in
`crates/rhdl-fpga/src/alto/`.  This crate lives at
`crates/rhdl-alto/` instead, **consistent with `rhdl-rv32i`'s
decision**: a CPU/microengine should not be bundled inside the
widget library — users who want widgets shouldn't transitively pull
in an Alto microengine.  Same engineering decision, same rationale.
